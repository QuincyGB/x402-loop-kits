Recovery Receipts

When the x402 fleet patrol finds a paid route broken — answering 403, 500, or nothing at all instead of a 402 payment challenge — that defect is recorded with a first-seen time. When the operator fixes it, we don't just take their word for it, and you shouldn't take ours either.

A recovery receipt is a signed record that a previously-defective route was re-probed twice, at least 10 minutes apart, and returned a clean, decodable 402 challenge both times. Each receipt is signed (EIP-191) by the patrol's agent wallet, 0xa4f183a6799F0310FcCC545B07F2DcC960223de2, so anyone can verify it was really issued by the patrol — and any tampering with a single field breaks the signature.

Receipt format (version fleet-recovery-receipt/v1)

FieldMeaning
origin / routeThe stall origin and the exact route URL that recovered.
defect_classThe patrol's defect classification when it was broken (e.g. unexpected_status, unreachable).
first_seenWhen the patrol first recorded the defect. Sourced from the patrol record — stated honestly in every receipt's source_note.
recovered_atTime of the second clean confirmation probe.
probesBoth confirmation probes: at, observed_status (402), and a challenge_summary.
receipt_idrr- + first 20 hex of SHA-256 over origin|route|defect_class|first_seen — deterministic, so a recovery is only ever receipted once.
signer / signatureThe agent wallet and its EIP-191 signature over the canonical form below.

Canonical form

fleet-recovery-receipt/v1
{JSON of the receipt without "signature", keys sorted, no spaces}

Signed as EIP-191 personal-sign (encode_defunct text) — the same scheme the patrol's nudge engine uses.

Verify a receipt

Paste a receipt JSON below. Verification runs in your browser (ethers.js via CDN) using exactly the canonicalization above. If the library can't load, use the Python snippet instead — it needs no trust in this page at all.

Or verify with Python

pip install eth-account   # or use the fleet venv
python3 recovery_receipts.py verify path/to/receipt.json
# prints {"valid": true, "signer": "0xa4f183a6799F0310FcCC545B07F2DcC960223de2"}

The verifier re-derives the canonical string from the receipt, recovers the signer from the signature, and checks it equals the agent wallet. Full source: recovery_receipts.py (verify_receipt()) in the fleet-checker.
