The Fleet-Health Nudge Inbox — an open convention

Protocol: fleet-health/v1 · Status: live on StallRow since 2026-10-27 · Reference implementation: app/services/nudge.py in QuincyGB/stall-row

Everything else in x402 is pull: a stall waits to be called, and a broken stall that never asks for a check never gets one. A nudge is the other direction — a signed knock on a stall's own door:

This route of yours is broken in this specific way. Here is the probe evidence. Here is the check that found it.

Any stall can publish an inbox, any checker can knock, and the stall's owner decides what a knock is worth. No accounts, no payment: inbound mail is not a product.

1. Publishing an inbox

Add one top-level extension to your /.well-known/x402 document (it is an extension, not a resource — it must not change your priced route count):

{
  "extensions": {
    "nudge": {
      "endpoint": "https://your-stall.example.com/v1/nudge",
      "accepts": ["fleet-health/v1"],
      "spec": "https://github.com/QuincyGB/x402-loop-kits/blob/main/nudge-inbox.md"
    }
  }
}

The endpoint accepts POST with a JSON body (§2). Publishing the extension is the entire integration — and the entire consent: an origin that publishes no inbox is never nudged by a conforming sender.

2. The nudge message

{
  "kind": "fleet-health-nudge",
  "protocol": "fleet-health/v1",
  "stall": "https://stall.example.com",
  "route": "https://stall.example.com/v1/check",
  "defect": {
    "code": "amount_mismatch",
    "expected": "50000",
    "observed": "70000"
  },
  "severity": "warning",
  "impact": "Your route charges 70000 but advertises 50000 (amounts in the asset's smallest units) — routers that verify declared prices will skip or flag it.",
  "action": {
    "summary": "Run the full Fleet Check diagnosis on this route now",
    "method": "POST",
    "url": "https://stall-row-production.up.railway.app/v1/fleet-check",
    "body": {"resources": ["https://stall.example.com/v1/check"]},
    "spec": "https://github.com/QuincyGB/x402-loop-kits/blob/main/nudge-inbox.md"
  },
  "evidence": {
    "probes": [
      {
        "at": "2026-10-27T22:40:00Z",
        "http_status": 402,
        "detail": "live challenge amount 70000 != declared 50000"
      }
    ],
    "source": "fleet-check"
  },
  "first_seen": "2026-10-27T22:40:00Z",
  "check_url": "https://stall-row-production.up.railway.app/v1/fleet-check",
  "sender": "0x19E7E376E7C213B7E7e7e46cc70A5dD086DAff2A",
  "signature": "0x172075…"
}

A knock is built to wake the stall up, not just to inform a human: it is severity-stamped (§5), it leads with the consequence (impact), and it is machine-actionable — the action block is a complete call a stall's own agent can execute in one step to order its own diagnosis, no human reading required.

FieldMeaning
kindfleet-health-nudge (or fleet-health-opt-out, §4)
protocolfleet-health/v1
stallThe origin the nudge is about (scheme + host, no path)
routeThe full resource URL, under stall
defect.codeMachine-readable defect class (§5)
defect.expected / defect.observedWhat the stall's own sources promise vs what the probe met. Strings or integers; amounts in the asset's smallest units, as strings
severitycritical or warning, from the mapping in §5
impactOne plain-language line naming the consequence of the defect, generated from the defect class and the observed numbers — factual and specific, no hype, no invented losses
actionA complete, executable call that diagnoses the affected route: {summary, method, url, body, spec}. body.resources names exactly the affected route
evidenceProbe records: timestamps, HTTP statuses, details. The receiver should be able to re-run the probe and land on the same facts
first_seenISO-8601 time the sender first observed the defect
first_knock_atEscalation knocks only (§6): ISO-8601 time of knock 1 for this incident
escalationEscalation knocks only (§6): the string "final"
check_urlWhere the receiver can buy or run the full check
senderThe sender's wallet address
signatureEIP-191 personal_sign over the canonical form (§3)

Receivers answer 200 {"ok": true, "stored": true|false, "duplicate": bool}. A re-send of an identical (sender, route, defect.code, first_seen) is a duplicate, not a second entry — except that an escalation knock (§6), which carries escalation: "final", is a distinct message from knock 1 even though it shares those four fields, and receivers must store it as its own entry.

3. The signature — canonical form

The signature proves who knocked and that the evidence was not altered in transit. To sign:

  1. Take the message object without the signature field.
  2. Serialize it as canonical JSON: keys sorted (recursively), no insignificant whitespace ("," / ":" separators), UTF-8, non-ASCII characters unescaped.
  3. Prefix the protocol line: fleet-health-nudge/v1\n + the JSON.
  4. Sign that text with EIP-191 personal_sign from the sender wallet.

To verify: rebuild the same text from the received message, recover the signer, and compare with sender (case-insensitive).

4. Opting out

A stall stops nudges by POSTing, to the sender's inbox (the inbox of whoever has been nudging it), a message of the same shape with kind: "fleet-health-opt-out", the stall it speaks for, and sender + signature from the wallet that stall's own discovery doc publishes as payTo:

{
  "kind": "fleet-health-opt-out",
  "protocol": "fleet-health/v1",
  "stall": "https://stall.example.com",
  "sender": "0x…the stall's payTo…",
  "signature": "0x…"
}

Control of the payTo is control of the stall's mail: an opt-out signed by anyone else is refused. A conforming sender checks the opt-out registry before every send and never nudges an opted-out stall again. Opt-outs are not rate-limited — leaving is a right, not mail.

5. Defect classes and severity

The classes the reference checker (Fleet Check) emits; senders may add their own, receivers should treat unknown codes as opaque:

CodeMeaning
amount_mismatchLive challenge amount ≠ the amount the stall's own discovery doc declares
payto_mismatchLive challenge payTo ≠ the declared payTo
unreachableNo HTTP response could be had at all
server_errorThe route answers 5xx to an unpaid probe
no_402The route answers 200 unpaid — no payment gate
unexpected_statusThe route answers a non-402, non-5xx status
challenge_undecodable402 answered, but the challenge does not parse or carries no accepts

Every nudge is stamped with a severity, mapped from the defect class — honestly, by consequence:

  • critical — the defect stops payment entirely: a buyer cannot obtain or use a payment challenge, so the route transacts nothing. unreachable, server_error, no_402, unexpected_status, challenge_undecodable.
  • warning — drift-class: buyers can still pay, but not as advertised. amount_mismatch, payto_mismatch. A code the mapping does not list also maps to warning — when in doubt, do not overclaim.

Severity is not decoration: it sets the escalation clock (§6).

6. Sender discipline (normative)

A nudge is a knock, not a battering ram. Conforming senders:

  • A bounded ladder per incident — two knocks, never more. Knock 1 lands at detection, severity-stamped with its impact and action. If the same defect is still present on a re-probe at least 24 hours later (critical) or 72 hours later (warning), the sender may knock exactly once more: an escalation carrying "escalation": "final" and first_knock_at (the time of knock 1), its impact stating that the defect is still broken, when it was first knocked, and that buyers are still affected. After the escalation, the incident is silent forever, however long it stays broken. An incident ends when a later probe shows the route healthy again; only a defect after that opens a new incident with a fresh ladder.
  • Honour opt-outs before every send — knock 1 and the escalation alike — including opt-outs learned since the last send.
  • Cap the volume — the reference engine sends at most 10 nudges per day, total, escalations included.
  • Only knock where an inbox is published (§1 is the consent).
  • Carry evidence, not vibes — every claim in a nudge must be reproducible from the probe records it carries.
  • Sign everything. An unsigned knock is indistinguishable from spam and should be refused as such.

Receivers, for their part, verify the signature, rate-limit per sender (the reference inbox allows 30 verified knocks per sender per hour), dedupe (§2), and answer malformed or forged mail with a clean 4xx — never a 5xx.

7. Status of this convention

Live, and deliberately small. StallRow's inbox is open (see its discovery doc) and the reference engine dogfoods the full loop on the fleet's own stalls. Outbound nudges to other stalls were enabled by the operator's explicit order on 2026-10-27: the reference sender now patrols the public catalogue in rotating slices and knocks only on stalls that publish an inbox, only for defects it has re-verified with its own probes. The engine's code default still ships off — the patrol is the armed runtime, and arming it remains the operator's explicit, separate decision.

The wake-up upgrade followed on 2026-10-28 (also the operator's order: "knock hard so they know to fix — we can't force them to check, but we need to wake them up"): severity stamps (§5), consequence-first impact lines, the machine-actionable action block, and the bounded two-knock escalation ladder (§6). A knock cannot compel a stall to do anything — the convention's whole design point is that the stall decides — but it can be unmissable, specific, and one step from a fix.
